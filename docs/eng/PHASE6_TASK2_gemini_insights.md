# GOODNUMBERS — `phase6_task2_implementation.md`

## TL;DR

Implement AI-driven cluster insights using Gemini 3.1 Pro (for deep clinical analysis) and Gemini 3.1 Flash (for metadata), and expand deterministic heuristics to match POC parity.

## Invariants (do not change)

- **No Medical Advice:** AI outputs must be framed as "observations" or "patterns," never "instructions" or "prescriptions."
- **Security:** Never log PII (emails). Keep `nightscoutToken` encrypted at rest.
- **Architecture:** Use the existing `HotspotDetector` and `worker.ts` pipeline in `backend/src`.
- **Mobile First:** Ensure cluster visualization and AI text render correctly on small viewports.
- **Workflow:** Red-Green-Refactor is mandatory. Commit format: `type(scope): P6_T2 <subject>`.

## Assumptions & Scope

- **{{AI_MODELS}}**: Gemini 3.1 Pro for insights/scripts; Gemini 3.1 Flash for title/description.
- **Current State**: `HotspotDetector` is working. `generateClusterInsights` is partially implemented (uncovered meals only).
- **Scope**: Port missing heuristics (post-bolus, pre-bolus), implement the multi-pass AI pipeline, and wire up the frontend to display the results.

## Objectives

1. **POC Parity**: Port `HIGH_AFTER_POSTBOLUSED_MEAL`, `HIGH_AFTER_PREBOLUSED_MEAL`, and `NON_MEAL_RELATED` heuristics from POC to `backend/src/lib/insights/cluster.ts`.
2. **AI Cluster Assessment**: For each cluster, generate a deep clinical assessment using Gemini 3.1 Pro, grounded in the deterministic heuristics.
3. **Podcast Pipeline**: Implement a multi-pass AI script generation:
   - Pass 1 (Pro): Comprehensive weekly assessment.
   - Pass 2 (Flash): Catchy title and description.
4. **Data Persistence**: Update the `GlycemicEventCluster` and `Journal` tables with structured AI results.

## Risks & Mitigations

- **AI Hallucinations**: Mitigation: strictly ground the prompt with deterministic "Ground Truth" findings (e.g., "AI, note that 3 of these 5 events were post-bolused").
- **Token Latency**: Mitigation: Process clusters in parallel or use summarized weekly notes for the overall podcast pass.
- **Unit Consistency**: Mitigation: Ensure `preferredUnits` are explicitly passed to all prompt generators.

## Method Outline (Deterministic → AI → Persistence)

1. **Mechanism - Deterministic Expansion**: Update `generateClusterInsights` to identify insulin timing (pre/post) by comparing treatment `date` with event `startTime`.
2. **Mechanism - Gemini Service**: Create `backend/src/lib/ai/gemini.ts` to encapsulate model-specific logic.
3. **Mechanism - Worker Update**:
   - Integrate `generateClusterAIInsight` into the cluster processing loop.
   - Add the final AI script/metadata passes after the hotspot engine finishes.
4. **Mechanism - UI Rendering**: Update `EventClusterCard.tsx` to handle the `insights` JSON field, using `whitespace-pre-wrap` for the AI text.

## Implementation Notes

- **Deterministic Logic**:
  - `PREBOLUSED`: Insulin `date` is 15–30 mins before `startTime`.
  - `POSTBOLUSED`: Insulin `date` is after `startTime`.
- **AI Prompts**: Prompts must be stored as templates in `backend/src/lib/ai/prompts.ts`.
- **Database**: `GlycemicEventCluster.insights` should store both deterministic and AI-generated text.

## Acceptance Gates

- **Gate 1**: `GlycemicEventCluster` contains deterministic insights for bolus timing (verified via unit tests).
- **Gate 2**: Each cluster has a unique `aiAssessment` field in the database.
- **Gate 3**: The `Journal` record has a title/description generated by Gemini 3.1 Flash.
- **Gate 4**: All data is correctly saved to the database and linked to the journal.
